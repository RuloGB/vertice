## Known Limitations (per rules.archive)

### 1. Clippy Cannot Be Verified Locally (W3 — Environment Constraint, Not Defect)

**Issue**: `cargo clippy --workspace --all-targets -- -D warnings` could not be run on this machine.
- MSVC toolchain on the system lacks the clippy component
- GNU toolchain fails with `dlltool.exe: program not found` (missing mingw-w64 linker)

**Mitigation**: CI's `rust` job covers all three platforms (macOS, Windows, Linux) with the full lint suite before merge.

**Recommendation**: No action needed. This is a local environment limitation, not a code defect. CI enforces clippy via the rust job on the three-platform matrix.

### 2. `export_to` Path Depth — Design/Code Reconciliation Item (S1)

**Issue**: Design.md (§5) originally specified `#[ts(export, export_to = "../../frontend/src/bindings/")]`. Empirically, three `..` are required, not two.

**Evidence**: Tested reproducibly with all three depths:
- `"../../frontend/src/bindings/"` → wrong location (one level short)
- `"../../../frontend/src/bindings/"` → correct (repo-root `frontend/src/bindings/`)

**All code uses the corrected three-`..` form.** The design document remains stale (shows two `..`). Whoever commits this PR should add a one-line note in `crates/vertice-core/src/model/mod.rs` documenting this quirk so future contributors adding a 9th type don't rediscover it.

### 3. `ClientKind` and `SearchRootKind` Variants Are Deliberately Provisional

**Scope**: `ClientKind { ClaudeCode, OpenCode }` and `SearchRootKind { Skill, Agent }` are closed enums but explicitly minimal.

**Rationale**: `plan-desarrollo-poc.md:T5/T6` enumerates only ClaudeCode and OpenCode as PoC clients; Cursor, Claude Desktop, Copilot are explicitly out of scope. Growing these enums is a normal, reviewable change in T4–T7, not a breaking redesign.

**Recommendation**: T4–T7 can add variants freely. Do not treat the current sets as final contracts.

### 4. Non-UTF-8 Path Serialization — Design Contract, Not Yet Exercised

**Statement**: `serde` serialization of `PathBuf` fails on non-UTF-8 paths (Windows WTF-8 surrogates, Linux arbitrary bytes).

**Design Contract (per design.md §6)**: From T3 onward, adapters meeting non-UTF-8 paths MUST emit `ScanIssue` with `path: None` and lossy-rendered `reason`, never construct a `Location` holding the non-UTF-8 `PathBuf`.

**T2 Status**: Zero disk I/O, so this code path is not exercised. The contract is stated and will be tested first in T3 when adapters perform disk walks.

## Decisions Worth Carrying Forward to T3–T10

### Identity Is Name + Kind, Never Content

- Identity MUST NOT incorporate file content, content hashing, or any `Location` data
- The string `"skill:issue-creation"` is stable across platforms and runs
- If identity later proves wrong after T8, only `identity.rs` and its tests move — no type shape changes
- **Collision case**: `issue-creation` with divergent content across three roots is ONE component with three locations, surfaced as a duplicate for review, not two entities

### Every Numeric Field Crossing IPC Is `u32`/`usize`

- `ts-rs` maps `u64`/`i64` to TypeScript `bigint`
- Tauri's JSON IPC delivers plain `number`
- Contract: all numeric fields are `u32`/`usize`, both map to `number`
- `ScanReport.duration_ms: u32` is the only numeric field; caps at ~49 days (not real)

### `ts-rs` Default Features MUST Stay ON

- `#[serde(rename_all = "camelCase")]` renames reach the generated `.ts` only if `serde-compat` feature is active
- If `default-features = false`, the renames silently fail, breaking the contract
- This is not a hint — default features MUST NOT be disabled

### Core Purity Invariant Holds Through TypeScript Generation

- `ts-rs` keeps T2 free of Tauri imports, enabling a future CLI
- Both `vertice-app` (Tauri) and future `vertice-cli` consume the same `ScanReport` types
- `vertice-app` adds only serialization at the IPC boundary; `vertice-cli` would add only formatting
- `cargo deny check bans` continues to verify zero Tauri transitive edges

### `ScanError` Requires `Serialize` + `TS`, NOT `Deserialize`

- **Invariant**: every `ScanError` variant payload MUST be owned serializable data (`String`, `PathBuf`, model enum)
- Never wrap foreign error types (`std::io::Error`, `serde_norway::Error`) without `.to_string()` at boundary
- Frontend generates TypeScript types but never constructs errors — only receives them from Tauri commands
- This invariant is **load-bearing** for IPC safety

### Import Allow-List for `model/` Module Is Strict

**Allowed**:
- `std::path` (PathBuf, Path)
- `std::time::Duration` (future: for non-measure-here use)
- `serde`, `ts_rs`, `thiserror`, `unicode_normalization`

**Forbidden** (by design):
- `std::fs`, `std::io`, `std::env`, `std::time::{SystemTime, Instant}`

This strict boundary is what makes the module "pure" and CLI-eligible.

## Size Exception

**Recorded in `tasks.md` §"Size Exception — Recorded":**

T2 was forecast at ~500–700 hand-written Rust lines + ~100–150 generated TypeScript lines + ~30 CI/config lines, totaling ~800–900 changed lines. The 400-line default PR review budget was exceeded, and chained PRs were recommended.

**User Decision (2026-08-17)**: Recommendation **declined**. T2 ships as a **single PR** (~650 changed lines) with these mitigations:

1. Commits are structured as reviewable work units (domain types → identity → tests → bindings → CI)
2. PR description must note that `frontend/src/bindings/*.ts` is machine-generated and should be skimmed, not line-reviewed
3. PR labeled `size:exception`

The exception is deliberate and documented. Reviewer receives the full change in one pass, with the domain modeling and `ts-rs` plumbing interleaved as it was developed.
