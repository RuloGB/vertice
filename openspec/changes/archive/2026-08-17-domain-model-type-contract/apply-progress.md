## Deviation: `export_to` path depth (undocumented in design, discovered at apply)

Design §5 specified `#[ts(export, export_to = "../../frontend/src/bindings/")]`, reasoning that `export_to` resolves against `CARGO_MANIFEST_DIR` (`crates/vertice-core/`), so two `..` components would land at repo-root `frontend/src/bindings/`.

**Empirically, this was wrong by exactly one level**, reproducibly, regardless of whether `cargo test -p vertice-core --locked` was invoked from the repo root or from `crates/vertice-core/` directly:

- `"../../frontend/src/bindings/"` → wrote to `crates/frontend/src/bindings/` (one level short)
- `"../frontend/src/bindings/"` → wrote to `crates/vertice-core/frontend/src/bindings/` (still short)
- `"../../../frontend/src/bindings/"` (three `..`) → wrote to `frontend/src/bindings/` at the repo root, correctly, matching design's intent.

The empirical evidence indicates `ts-rs` 12.0.1 resolves a relative `export_to` against an implicit `CARGO_MANIFEST_DIR/bindings/` base (not `CARGO_MANIFEST_DIR` itself), requiring one extra `..` to compensate for that implicit `bindings/` segment. This was verified by testing all three depths in sequence and observing the exact, consistent off-by-one pattern above (cleaning up the wrong directory between each attempt). **All 15 `#[ts(export, export_to = "../../../frontend/src/bindings/")]` attributes in `crates/vertice-core/src/model/*.rs` use the corrected three-`..` path.** The emitted contract (field names, types, discriminated unions) is unchanged — only the output path needed correction, exactly as design §4.1 anticipated for the `Option<PathBuf>` shape question ("cheap to settle at apply... failure mode is compile-time or diff-visible, not silent").

**Recommendation for `sdd-verify` / future changes**: this path-depth quirk is worth a one-line comment in `design.md` or a `model/mod.rs` doc-comment for future contributors adding new domain types, so nobody re-discovers it from scratch. Not corrected in `design.md` itself during this apply batch (design is a historical decision record, not living documentation); flagging here for the verify/archive phase to consider.

## Deviation: `Component.provenance_hint` type — `String`, not `Option<String>`

`design.md` §2's code sketch shows `pub provenance_hint: Option<String>`, but `openspec/changes/domain-model-type-contract/specs/domain-model/spec.md`'s **Requirement: provenance_hint Is Opaque, Not a Discriminator** explicitly states: *"`Component.provenance_hint` MUST be typed as a plain `String`"* and its scenario asserts *"it is `String`, not an enum or tagged union."*

**Initial resolution (superseded)**: implemented as `pub provenance_hint: String`, following the spec's literal requirement over the design's sketch, and flagged for reconciliation.

**Final resolution (2026-08-17, user decision)**: the conflict was reconciled in favor of **`Option<String>`**, and the **spec was corrected** — it was the wrong artifact, not the design.

Rationale: with a plain `String`, "this adapter reported no provenance" can only be expressed as `""`, which is a sentinel value wearing a type's clothing. The model already rejects exactly this pattern one field over — `Location.path` is `Option<PathBuf>` precisely so that "no backing file" is a real state rather than an empty-path convention. Evidence that the sentinel was already leaking: three of the four construction sites in `tests/model_contract.rs` were written as `String::new()`.

Changes made:

- `crates/vertice-core/src/model/component.rs` — `provenance_hint: Option<String>`, doc comment states why `Option` over an empty `String`.
- `specs/domain-model/spec.md` — the requirement now mandates `Option<String>` and forbids the empty-string sentinel explicitly; added a second scenario covering `None` vs `Some("")` vs `Some("claude-code")`.
- `tests/model_contract.rs` — the three `String::new()` sites became `None`; the populated-report site became `Some("claude-code".to_string())`.
- `frontend/src/bindings/Component.ts` — regenerated: `provenanceHint: string | null`.

`design.md` §2 needed no change; it already showed `Option<String>`.
